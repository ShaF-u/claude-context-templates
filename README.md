# コンテキスト削減テンプレート

どのプロジェクトでも流用できる、Claude Code向けのコンテキスト削減手段をまとめたもの。
すべて「Markdownを書くだけ」で実現でき、追加のツール開発は不要。

## フォルダ構成

読み手によって3つに分けている。「AIに毎回読ませる価値があるか」で分類の基準を決めている。

- **`AI/`** — AIに読ませる前提のファイル。探索を省略させるための地図など。
  簡潔・構造化されていることを優先する。
- **`Docs/`** — 人間向け。背景・経緯・運用ルールなど、AIに常時読ませる必要のないもの。
- **`Shared/`** — 両方が読む前提のファイル。命名規則など、人間とAIが同じルールに従う必要があるもの。

## 現在の中身

- `AI/STRUCTURE.md` — フォルダ構成マップのテンプレート＋探索不要なパスのリスト。
  プレースホルダを実際の構成に置き換えて使う。
- `AI/DECISIONS.md` — 決定済み事項の短いリスト。AIに同じ提案を繰り返させないためのもの。
  詳しい経緯は書かず、結論だけを書く。
- `Shared/NAMING.md` — 命名規則。変数・関数・クラス・DB・API・ブランチ名の命名ルール。
- `Shared/CONVENTIONS.md` — 命名以外のコーディング規約。今のところ「コメントは極力書かない」のみ。

## 導入手順

1. 使うプロジェクトのルートに `AI/` `Docs/` `Shared/` ごとコピーする
   （または中身だけプロジェクトの `docs/` 等に統合してもよい）。
2. `AI/STRUCTURE.md` のプレースホルダを実際のフォルダ構成・機能配置に置き換える。
3. `Shared/NAMING.md` `Shared/CONVENTIONS.md` はプロジェクトの実際のルールに合わせて調整する。
4. プロジェクトの `CLAUDE.md` から `@AI/STRUCTURE.md` `@Shared/NAMING.md` のように参照する、
   またはCLAUDE.mdの冒頭に「作業前にこれらを読むこと」と一行書いておく。
5. フォルダ構成が変わるたびに `STRUCTURE.md` を更新する（放置すると誤誘導のリスクの方が大きい）。

## 確認済みの関連機能（自分のシステム定義・過去の調査で裏付けた範囲のみ）

- **CLAUDE.md**: プロジェクトルートに置くとセッション開始時に自動で読み込まれる。
- **Directory-scoped Skill**: `.claude/skills/` 配下のSkillはパスの接頭辞付きで一覧される
  （例: `apps/web:deploy`）。モノレポで特定フォルダ専用のSkillを作れる。
- **サブエージェント定義（`.claude/agents/*.md`）**: Markdown + フロントマターで
  カスタムサブエージェントを定義できる。サブエージェントの調査過程（大量のファイル読み込み等）は
  メインの会話には残らず、要約だけが返る。
- **Memory**: 索引ファイル（MEMORY.md相当）は一定行数を超えると切り詰められる仕様。
  索引は簡潔に、詳細は個別ファイルに分ける。
- **MCPサーバーの整理**: 使っていないMCPサーバーは接続を切る。接続されている限り、
  ツール定義（名前・説明・パラメータ）がコンテキストに乗り続ける。

## 検証できず採用しなかった情報

調査の過程で「`.claude/rules/` ディレクトリでパス指定のルールを自動適用できる」
「Skillのフロントマターに `paths:` を書くと特定ファイルで自動発動する」
「MEMORY.md索引は25KBまで」といった情報が出てきたが、**公式ドキュメントで直接確認できず、
生成AIの調査結果に不審な混入（指示のような文言）の疑いがあった**ため採用していない。
これらを使いたい場合は、実際に試すか公式ドキュメントで裏を取ってから使うこと。

## 検討したが不採用にしたもの

- **各主要フォルダに短いREADME.mdを置く**: 使いづらいと判断し不採用。
- **ドメイン用語 → コード上の名前の対応表**: 対象プロジェクト（ゲーム）がまだ決まっていないため、
  今の時点では作りようがない。プロジェクトが決まってから追加を検討する。
- **`AI/IGNORE.md`を独立ファイルにする**: 分けすぎると逆に分かりにくくなるため、
  `AI/STRUCTURE.md`内の1セクション（探索不要なパス）として統合した。

## 保留中

- **`Shared/BUILD.md`**（ビルド・テスト・実行コマンド集）: 今は不要と判断。
  Skillを導入した際に必要になる可能性があるため、その時点で再検討する。

## 基本方針

- 「圧縮」より「そもそも読み込ませない・選別する」方を優先する。
  コードは非可逆圧縮と相性が悪い（1文字の違いで意味が変わるため）。
- 重い調査・探索はサブエージェント（fork等）に投げ、結論だけをメインの会話に残す。
- 常時ロードされるもの（CLAUDE.md本体、Memory索引、接続中のMCPサーバーのツール定義）を
  小さく保つことが、個別の圧縮テクニックより効果が大きい。
